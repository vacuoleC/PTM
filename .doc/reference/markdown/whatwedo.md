# 跟着AI，我做了什么？

## 1. 预备部分

### 1.1. 环境搭建   

```bash
conda create -n PTM-encoder python=3.11
pip3 install cptac
```

### 1.2. load.py做了什么

- 把 cptac 的数据根目录从 conda 站点包内,改到本项目的 ./data  
- 跳过 cptac 自带的"md5 不一致就删掉 93MB 重下"逻辑 + 缺文件时重试  
- 得到cptac数据根，`ph.shape = (212, 80270)`，`index`是`shample ID`如`C3L-00081.N`，`culumns`是`(Gene, Site) multy-index`如`('TP53', 'S15')`

### 1.3. clinical_tital.py做了什么

- 组织类型、T分期、N分期：太脏不用
- 总分期（Stage）：早期85人，晚期22人。缺点：晚期人太少（22个），做AI模型时，这22个人一拆开，每组就剩4-5个人，数据太薄，容易出错。
- 分化级别（Grade）：中分化58人，低分化48人。优点：两边人数差不多（58 vs 48），数据均匀，AI学起来最稳。

### 1.4. 为什么要做这些

我们希望探索有没有必要上encoder模型，还是说不嵌入用TF也能学到足够的特征空间，所以需要设计一个可以看出有无encoder器效果的实验，现在就是在挑选应该使用哪个数据集来进行实验。

### 1.5. focus.py做了什么

- 发现3个数据方之间数量无法对齐
- LSCC的grade和UCEC承重墙差太远
> 没有一个标签在三个队列上都干净。 这不是选择题做错了，这是数据的真实约束——CPTAC 这三个队列的临床构成本来就不一样，肺癌和子宫内膜癌的分级分期分布天生不同。
- 三个可能的问题：  
    1. UCEC被砍到42 vs 27，这是承重墙上最脆弱的状态
    2. 这个任务本身可能没信号，但grade任务失败只说明「这把尺子在这批数据上不好使」，路由到下一个方案（跨组织迁移，或回退到磷酸化广度轨
    3. 跨组织这条可能过不了，而这次不是因为没信号，是因为标签在 UCEC 上先天不足

## 2. Phase 0：三模态数据是否能真正对齐？

### 2.1. coverage_matrix.py 做了什么

这个脚本不训练模型，只检查每个队列中是否有病人同时拥有：

- 磷酸化（phosphoproteomics）
- 乙酰化（acetylproteomics）
- 母蛋白丰度（proteomics）

样本 ID 以 `.N` 结尾的是正常样本，其余是肿瘤样本。只有三张表中都存在的病人，才可以进入后续的多模态 PTM 实验。

实际结果保存在 `outputs/coverage_matrix.csv`：

| 队列 | 三模态共同正常样本 | 三模态共同肿瘤样本 | 能否进入实验 |
|---|---:|---:|---|
| LSCC | 102 | 110 | 可以 |
| LUAD | 102 | 111 | 可以 |
| UCEC | 49 | 103 | 可以 |

这一步证明的是：三个队列的数据覆盖足够，能够进行多模态 PTM 分析。它**还没有**证明 PTM 有疾病预测信号，也没有证明 encoder 有用。

### 2.2. build_matrix.py 做了什么

目前先以 LSCC 为例，把后续矩阵构建前的数据整理流程写清楚：

1. 原始三张表的形状分别是：
   - 磷酸化：`(212, 80270)`
   - 乙酰化：`(220, 21110)`
   - 蛋白组：`(212, 13715)`
2. 取三模态共同样本后，三张表都对齐为 212 位病人；行顺序也用 `assert` 检查过完全一致。
3. PTM 特征保留 `(Name, Site)`，即“哪个基因的哪个修饰位点”；蛋白组保留 `Name`，即“哪个母蛋白”。
4. 乙酰化中有 1,581 个位点缺少 `Name`。例如只有 `K685`、却不知道属于哪个蛋白；它们无法匹配母蛋白，因此从后续的核心残差矩阵中排除。
5. 清理后可用特征数：
   - 磷酸化：80,270
   - 乙酰化：19,529
   - 蛋白组：13,715
6. 简化列名后仍有重复测量，暂时只统计、还没有合并：
   - 磷酸化：6,380 个重复列（5,933 个重复位点组）
   - 乙酰化：9 个重复列（9 个重复位点组）
   - 蛋白组：956 个重复列（767 个重复基因组）

### 2.3. 重复特征合并与母蛋白匹配

同一个 `(Name, Site)` 的 PTM 测量、或同一个 `Name` 的蛋白组测量，按每一位病人取中位数合并。合并结果：

- 磷酸化：80,270 列 → 73,890 列
- 乙酰化：19,529 列 → 19,520 列
- 蛋白组：13,715 列 → 12,759 列

接着检查每个 PTM 位点能否按照 `Name` 匹配到母蛋白：

- 磷酸化：72,361 / 73,890 = **97.93%**
- 乙酰化：19,331 / 19,520 = **99.03%**

不能匹配母蛋白的 PTM 位点不进入残差校正。清理后用于校正的矩阵形状为：

- 磷酸化：`(212, 72361)`
- 乙酰化：`(212, 19331)`
- 蛋白组：`(212, 12759)`

### 2.4. 化学计量校正（PTM ~ 母蛋白回归残差）

先用一个位点验证回归逻辑。以 `M6PR-S267` 为例：

```text
PTM = 0.1406 + 0.5280 × 母蛋白 + 残差
```

残差和母蛋白的相关系数为 0，说明母蛋白总量的线性影响已经被去除。随后对所有可匹配位点逐一做同样的回归，并保留残差。

残差矩阵的结果：

| 修饰类型 | 残差矩阵形状 | 少于 10 个有效样本而跳过的位点 | 缺失值比例 | 检测率 ≥50% 的位点数 |
|---|---:|---:|---:|---:|
| 磷酸化 | `(212, 72361)` | 7,556 | 64.41% | 22,721 |
| 乙酰化 | `(212, 19331)` | 1,759 | 59.06% | 7,346 |

缺失率较高是 PTM 位点测量稀疏的正常现象。现在只报告检测率，不在这里按检测率删除位点；正式模型会在每一个训练折内过滤、填补和标准化，避免测试集信息泄漏。

### 2.5. 多类 PTM 矩阵与保存产物

给每个特征增加 `Modification` 层级，明确区分 `phosphorylation` 和 `acetylation`，再横向拼接两张残差矩阵：

```text
多类 PTM 残差矩阵：212 位病人 × 91,692 个特征
列层级：Modification / Name / Site
```

同时由样本 ID 的 `.N` 后缀生成 LSCC 肿瘤/正常标签：肿瘤 110 人、正常 102 人。产物已保存：

- `outputs/lscc_multi_ptm_resid.pkl.gz`
- `outputs/lscc_tumor_normal_labels.csv`

### 2.6. 训练折内预处理模块

`build_matrix.py` 的第一版已完成。已新建 `scr/transformers.py`，其中有两个 sklearn 兼容的预处理组件：

- `DetectionFilter`：只保留训练折中检测率达到阈值的特征；
- `MedianImputer`：用训练折每列的中位数填补缺失值。

它们的 `fit()` 只在训练折上执行，测试折只能调用已经学到的 `transform()` 规则，因此不会偷看测试集。文件中曾将 `DetectionFilter` 拼错为 `DatectionFilter`，现已更正；在 `scr/` 目录中已验证可以正常导入。

### 2.7. 下一步要做什么

下一步新建 `scr/run_floor.py`，读取保存的残差矩阵与肿瘤/正常标签，先构造“按病人分组”的交叉验证。样本 `C3L-00081` 与 `C3L-00081.N` 分别是同一位病人的肿瘤和正常，必须放进同一个训练折或测试折，不能拆开。

分组验证完成后，再将 `DetectionFilter`、`MedianImputer`、标准化和 Logistic Regression 放进同一个 sklearn Pipeline，进行无数据泄漏的 LSCC 肿瘤 vs 正常 floor 实验。

### 2.8. LSCC 肿瘤 vs 正常 floor 实验

`run_floor.py` 已完成。它读取保存的残差矩阵和标签，将 `.N` 后缀去掉后按病人 `GroupKFold` 分组：212 个样本对应 110 位独立病人，因此同一位病人的肿瘤与正常不会被拆到不同折。

每一个训练折内的管线为：

```text
DetectionFilter → MedianImputer → StandardScaler → 分类器
```

线性基线额外接 PCA（30 维），随后使用 Logistic Regression；非线性主模型使用 XGBoost。两者都使用相同的 5 折病人分组、AUPRC/MCC/balanced accuracy/F1 指标。

| 模型 | AUPRC（5 折均值 ± 标准差） |
|---|---:|
| PCA + Logistic Regression | 0.9919 ± 0.0160 |
| XGBoost | 0.9940 ± 0.0134 |

LSCC 中肿瘤/正常的随机 AUPRC 基线约为 `110 / 212 = 0.519`，因此多类 PTM 残差中存在极强信号。但 XGBoost 相比线性模型只提高约 0.002，远小于折间波动，说明这个任务接近饱和；它不能用于判断 encoder 是否必要，也不足以证明乙酰化带来增量。

这三组结果说明：在 LSCC、LUAD 和 UCEC 中，母蛋白校正后的多类 PTM 残差都含有非常强的“肿瘤 vs 正常”信号，且该现象并不局限于肺癌队列。它是 Phase 0 的**疾病信号存在性证据**，但仍不能证明 encoder 优于传统方法，也不能直接外推到分期、分级或预后等临床任务。

### 2.11. Phase 0 统计结案（置换 null、BH 校正与功效诊断）

主模型固定为 XGBoost，主指标固定为 AUPRC。对 LSCC、LUAD、UCEC 分别进行 100 次样本标签置换；每一次置换都保留原来的病人分组交叉验证划分，并在训练折内完成检测率过滤、中位数填补和标准化。三个队列的经验 p 值随后一起做 Benjamini-Hochberg（BH）校正。

| 队列 | 真实 AUPRC | null AUPRC（均值 ± 标准差） | 经验 p | BH q |
|---|---:|---:|---:|---:|
| LSCC | 0.9846 | 0.5540 ± 0.0423 | 0.0099 | 0.0099 |
| LUAD | 1.0000 | 0.5538 ± 0.0374 | 0.0099 | 0.0099 |
| UCEC | 0.9960 | 0.7096 ± 0.0398 | 0.0099 | 0.0099 |

三队列在 100 次置换中都没有出现一次 null 分数达到真实分数，因此得到可达到的最小经验 p 值 `(0 + 1) / (100 + 1) = 0.0099`。BH 校正后仍均为 0.0099，说明结果不是在三队列同时检验下偶然出现的高分。

UCEC 是唯一非肺组织队列，也是跨组织证据的守门员。它进行了 10 次重复、每次 5 折的分层病人分组验证：50 个测试折的 AUPRC 均值为 0.9937，标准差为 0.0064，折间分布的 2.5%–97.5% 分位数为 0.9814–1.0000。这里的区间是重复 CV 的折间稳定性描述，不应误称为独立样本的置信区间；但它表明 UCEC 的结论并非由某一个偶然划分支撑。

学习曲线显示：

- LSCC：训练样本从 42 增至 84 后，平均 AUPRC 从 0.8677 升至 0.9827，之后维持在约 0.985–0.987。
- LUAD：42 个训练样本时已达 0.9384，127 个训练样本起达到 1.0000。
- UCEC：30 个训练样本时为 0.7854；增至 60 个时已达 0.9892，完整训练折为 0.9950。

因此，当前数据没有显示“信号接近随机、但可能只是功效不足”的情形；相反，三个队列都显示出远高于各自肿瘤比例基线的稳定疾病信号。

**Phase 0 正式结论：pass。** 多类 PTM 丰度残差中存在可学习的肿瘤 vs 正常信号，且至少在肺组织（LSCC/LUAD）与子宫组织（UCEC）中复现；项目唯一的绝对 no-go 门不触发。这个结论只限于 CPTAC 可测到的两类 PTM 丰度表征与两个组织类别，不能声称“泛癌”广泛成立，也不证明 encoder 优于传统模型。

本阶段的正式产物：

- `outputs/phase0_xgboost_null_summary.csv`
- `outputs/{lscc,luad,ucec}_phase0_xgboost_null_scores.csv`
- `outputs/{lscc,luad,ucec}_phase0_xgboost_learning_curve.csv`

下一步：不再在饱和的肿瘤 vs 正常任务上比较模型，而是先审计 `clinical` 和 `derived_molecular` 中可用的肿瘤内标签（分子亚型、分期、分级等），选择一个有足够类别规模和难度的任务；若没有合格标签，再预注册肺癌训练 → UCEC 测试的跨组织迁移任务。在该难任务上，才比较磷酸化单模态 vs 多类 PTM，以及 PCA/传统模型 vs encoder。

### 2.12. Encoder 必要性阶段：已确认的范围、资料与算力约束

本阶段的目标限定为完成 **encoder 是否必要的证据包**，而不是一次性完成完整的临床解释或外部临床验证。具体顺序是：

1. 从 CPTAC 的 `clinical` 与 `derived_molecular` 中审计并选择一个有足够样本量、类别平衡和难度的肿瘤内任务；若没有合格标签，则预注册“肺癌队列训练 → UCEC 测试”的跨组织迁移任务。
2. 在完全相同、按病人分组且训练折内预处理的划分上，比较磷酸化单模态与磷酸化+乙酰化多类 PTM。
3. 在同一困难任务上，比较传统/PCA 基线与**不接触下游监督标签、参数冻结**的 encoder；结果仅作为模型选择与路线诊断，不能推翻已通过的 Phase 0 信号存在性结论。

用户已明确允许使用公开 qPTM 数据、公开论文和公开的 COMPASS-PTM/PTM-Mamba 资料作为研究资源。后续使用时必须记录数据来源、许可、预训练用途以及“encoder 不接触下游标签”的边界；COMPASS 的预测结果仍不得作为 encoder 输入。

远端算力机的执行规则已确定：本地代码先在 `D:\\coding\\PTM` 原子提交，再推送到 GitHub 仓库 `vacuoleC/PTM`，远端从 GitHub 同步到唯一允许的项目路径 `/data/PTM`。远端只可使用既有 Conda 环境 `ptm-encoder`，不得在 `/data/` 以外建立任何项目、环境或临时文件，也不得探测、修改或破坏服务器的其他环境。远端产物先写入 `/data/PTM/outputs`，随后通过 GitHub 同步回本地；每次运行都要记录 commit、命令、结果与状态。

### 2.15. 多类 PTM 增量统计结论

## 2.20 qPTM 条件覆盖审计（2026-07-24）

- 对 11,482,553 行原始表进行了分块审计，仅使用无监督的物种、修饰、位点、样本、条件与肽段 Log2Ratio 字段。
- 人类磷酸化：5,001,481 条事件、222,919 个蛋白-位点、17,029 个基因、**1,167 个 PMID×样本×条件上下文**、564 个样本、275 篇文献；肽段 Log2Ratio 完整率 100%。
- 人类乙酰化：227,954 条事件、34,024 个蛋白-位点、6,904 个基因、**82 个条件上下文**、25 个样本、25 篇文献；肽段 Log2Ratio 完整率 100%。
- 结论：qPTM 具备构造条件级、标签冻结预训练样本的最小数据条件，尤其磷酸化条件丰富；但乙酰化覆盖远小于磷酸化。qPTM 是条件扰动表，后续应构造 condition×site 稀疏矩阵并明确其与 CPTAC 病人绝对/残差表征的域差异，而不能直接按样本行拼接。

## 2.21 qPTM 与 CPTAC 共同位点覆盖（2026-07-24）

- 使用三 CPTAC 队列共同特征、仅保留可解析的单一位点（磷酸化 `S/T/Y+位置`，乙酰化 `K+位置`），再按 `修饰类型 + Gene name + Position` 与 qPTM 对齐；这是保守的位点位置匹配，尚未把带多个修饰残基的 CPTAC 特征纳入。
- 磷酸化：CPTAC 32,301 个简单位点中 25,518 个可在 qPTM 匹配，**CPTAC 覆盖 79.00%**；qPTM 222,494 个位点中 11.47% 命中 CPTAC，约 44.19% 的 qPTM 磷酸化事件位于这些共同位点。
- 乙酰化：CPTAC 7,863 个简单位点中 5,793 个可匹配，**CPTAC 覆盖 73.67%**；qPTM 33,987 个位点中 17.04% 命中 CPTAC，约 32.14% 的 qPTM 乙酰化事件位于共同位点。
- 结论：共同特征覆盖足以支持 qPTM→CPTAC 的共同位点预训练；但 qPTM 包含大量 CPTAC 未测位点，构造训练矩阵时应以共同位点作为可迁移输入空间，并保留 qPTM-only 位点不进入本轮公平比较。

## 2.22 Encoder 必要性任务结论（2026-07-24）

- qPTM 的磷酸化与乙酰化虽然分别具有 1,167 和 82 个条件上下文，但两类 PTM **共同的 PMID×样本×条件上下文只有 2 个**。因此不能诚实构造大规模配对多类 qPTM 条件矩阵；把单修饰条件横向拼接会制造伪配对与数据泄漏式假象。
- 结合 LSCC G2/G3 的公平 encoder 对照（encoder 相对 PCA 无显著增益）与 qPTM 配对限制，当前结论是：**不值得继续投入 qPTM+CPTAC 联合多类条件 encoder 的实现与大规模训练**。
- 这不是 Charter 的项目 no-go。Phase 0 已通过；结论仅将资源路由到 PTM-only 生物学锚点、真正配对的多类 PTM 数据，或未来以单修饰 encoder 为明确独立目标的方案。
- 已生成并提交 `ENCODER_NECESSITY_REPORT.md` 与函数级 `README.md`；正式结果、限制与下一步均已纳入报告。当前 `whatwedo.md` 已完成本轮证据链记录。
