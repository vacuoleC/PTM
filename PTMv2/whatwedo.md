### E1.1 — 病人独立性、标签完整性与类别结构审计

- 父事件：E1；同级比较组：E1 数据与标签可行性审计；状态：进行中

- 怎么做：实现 `scr/audit_cohort.py`，按 `config/project.yaml` 的路径读取只读矩阵与标签；检查 ID 唯一性、矩阵/标签交集、sample/patient ID 一致性、二元 target 完整性和类别计数；输出可复现的表、类别图与审计报告，并用 `tests/test_audit_cohort.py` 覆盖核心完整性检查。
- 结果怎么样：待运行。标签列结构已被只读核验为 `sample_id`、`patient_id`、`raw_label`、`class_name`、`target`；矩阵索引名为 `Patient_ID`。
- 证据与决策：本次原子提交包含脚本、测试、配置输出路径与进行中记录；运行输出将进入下一次原子提交。审计通过后进入 E1.2；若发现 ID 或标签异常，则建立 E1.1 的失败子分支。

### E0.3 — 主任务、终点与推断规则冻结

- 父事件：E0；状态：已完成
- 为什么做：防止根据模型结果更换标签、特征阈值或统计标准，并让后续的失败也可被解释为预先定义任务的结果。
- 怎么做：创建版本化 `study_design.yaml`，将 LSCC G2 vs G3 冻结为主任务（106 位病人，G2=58、G3=48）；预注册训练折内处理、5×10 外层/3 折内层患者级验证、两条主模型、两条探索模型、500 次完整主管线置换、学习曲线及多视图/encoder 重新开门条件。

- 证据与决策：`study_design.yaml`、`config/project.yaml`、本地日志事件 E0.3。此为设计冻结而非数值实验，因此以版本化设计文件为证据，不制作装饰性图。下一步进入 E1.1，审计病人独立性、标签完整性和类别结构。
